# UI plan: crop overlay readability and square video edges

## Goal
Improve the crop preview so the overlay does not compete visually with native video controls, and ensure the crop frame is fully visible for edge-to-edge aspect ratios such as `16:9`.

## Current findings
- `ui/src/components/VideoRangeEditor.jsx` renders the crop overlay directly above `<video controls>`.
- `ui/src/App.css` applies `border-radius: 14px` to both `.video-preview` and `.video-preview-shell`.
- Because the overlay sits on top of native browser controls, the bottom control bar and central play button remain visible through the masked areas.
- Because the preview shell is rounded and also clips overflow, the crop frame can appear cut off near the corners and edges.

## Recommended solution
Use a dedicated crop stage for the visual frame and move playback controls out of that stage when a crop preset is active.

This keeps the preview clean, removes the browser play icon from the masked region, and avoids fighting native control styling that is difficult to customize consistently.

## UX approach
1. Keep the video element inside the preview stage, but disable native `controls` while the crop overlay is visible.
2. Add a small external transport row below the preview stage with only the essentials:
   - play/pause button
   - current time / duration label
3. Keep click-to-play on the preview itself so playback remains quick.
4. Reduce visual weight of the overlay slightly:
   - keep the yellow frame
   - make the mask a little softer or slightly more neutral
   - optionally add a subtle inner glow or outline on the frame for contrast
5. Remove rounding from the actual video stage:
   - `.video-preview { border-radius: 0; }`
   - `.video-preview-shell { border-radius: 0; }`
   - keep rounded corners on the outer panel only

## Lower-effort fallback
If the goal is the smallest possible diff, implement only these two changes:
1. remove border radius from the video preview and shell
2. reserve a clear bottom strip by shrinking the overlay area above native controls

This is simpler, but it does not solve the central native play button and will still depend on browser-specific control rendering.

## Implementation steps
1. Update `VideoRangeEditor.jsx` to derive an `isOverlayVisible` playback mode and conditionally hide native controls when crop is active.
2. Add local playback state and handlers for:
   - play/pause
   - current time syncing
   - metadata duration display
3. Render a compact control row below `.video-preview-shell` instead of relying on native controls during crop editing.
4. Make the preview stage itself square-edged by removing border radius from the video and shell.
5. Tune overlay styling in `App.css` so the frame remains readable without feeling heavy.
6. Add or update tests in `ui/src/components/VideoRangeEditor.test.jsx` to cover:
   - crop mode hides native controls
   - custom play control renders in crop mode
   - non-crop mode can still show native controls if desired
   - crop frame remains rendered with expected geometry

## Notes on scope
- This can stay a targeted UI change inside `VideoRangeEditor.jsx` and `App.css`.
- No backend work is needed.
- Translation strings may need 1-2 new labels if the custom control row uses text buttons.

## Validation
- Existing component tests should be extended rather than replaced.
- Manual runtime verification is not included in the plan because project rules require explicit user approval for that step.

## Recommendation summary
Best balance of UX and implementation cost:
1. hide native controls only while crop overlay is active
2. add a minimal external play/pause row
3. remove border radius from the video stage entirely
