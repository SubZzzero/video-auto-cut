# Add Crop Frame Snapping

## Goal
Add snapping for the draggable crop frame in the preview so manual positioning feels more precise without changing the backend API or processing flow.

## Current State
- `ui/src/components/VideoRangeEditor.jsx` already supports free drag for the crop frame through `pointerdown` + global `pointermove` handlers.
- Dragged coordinates are normalized through `resolveCropPlacement(...)`, which already clamps the crop window inside the source bounds.
- `ui/src/App.jsx` persists `cropX` and `cropY` in queue state and already sends them through the existing processing flow.
- Backend crop logic in `app/video/crop.py` already accepts explicit crop origins, so snapping can stay frontend-only.
- Existing UI tests cover overlay visibility, geometry updates, and clamped drag, but there are no focused crop utility tests yet.

## Proposed Changes
1. Add dedicated snapping constants in `ui/src/config/constants.js`.
   - Keep the snap threshold configurable in one place.
   - If needed, keep snap target toggles or guide positions centralized as well.

2. Extend `ui/src/utils/crop.js` with snapping helpers.
   - Add one helper that receives the requested crop origin plus source/crop dimensions.
   - Snap only when the dragged position is within a configurable threshold.
   - Reuse existing crop placement math so snapping still respects frame bounds.

3. Apply snapping during drag updates in `ui/src/components/VideoRangeEditor.jsx`.
   - Keep the current drag model.
   - Insert snapping just before calling `onCropPositionChange(...)`.
   - Preserve current clamp behavior as the final safety layer.

4. Optionally expose lightweight visual feedback in `VideoRangeEditor.jsx` and `ui/src/App.css`.
   - If the chosen UX needs it, show a subtle active-guide state when snapping is engaged.
   - Keep styling minimal so the existing preview layout stays unchanged.

5. Update user-facing copy only if needed.
   - `ui/src/i18n/translations.js` currently says crops stay centered, which no longer matches draggable crop behavior.
   - Adjust the hint to mention manual positioning and snapping if we include it in the visible UX.

6. Add tests before verification.
   - Add utility tests for snap threshold behavior and edge cases.
   - Extend `ui/src/components/VideoRangeEditor.test.jsx` with drag cases that verify snapping and clamping interaction.
   - Cover non-snap movement to ensure free drag still works outside the threshold.

## Scope Notes
- No backend changes are required.
- No API schema changes are required.
- No dependency installation is required.
- This fits the current architecture and step order because it is a frontend-only enhancement on top of the existing crop editor.

## Confirmed Product Decision
The crop frame should snap to video edges and exact center only.

## Execution Notes
- Prefer one reusable helper in `ui/src/utils/crop.js` instead of embedding snap math directly in the component.
- Use source-space coordinates for snap decisions so behavior stays stable regardless of rendered preview size.
- Keep the final snapped position flowing through existing placement/clamp logic.
- Cover left, right, horizontal center, top, bottom, and vertical center snap cases in tests.
