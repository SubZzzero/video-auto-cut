# Plan: align Controls inputs on one visual line

## Goal
Adjust the settings controls so the `Crop` select and `Duration` number input render on the same visual baseline and feel consistent with each other.

## Current findings
- The relevant markup is in `ui/src/components/Controls.jsx`.
- The current layout uses two `setting-card` blocks inside `.settings-grid`.
- Shared control styles live in `ui/src/App.css`.
- Both controls currently only have `min-height: 48px` in `.setting-card select, .setting-card input[type='number']`.
- Because `select` and `input[type='number']` keep browser-native appearance/details, they can render with slightly different inner box metrics, which matches the mismatch visible in the screenshot.

## Implementation steps
1. Update `ui/src/App.css` to normalize the settings controls used inside `.setting-card`.
2. Replace the current `min-height` rule with a stricter shared control sizing rule for both the select and number input.
3. Give both controls the same explicit height and vertical alignment behavior so they sit on the same line visually.
4. Normalize browser rendering where needed with `appearance` on the settings controls, while keeping the existing dark theme and focus states intact.
5. If the number input spinner still shifts the field height in Chromium, add a scoped rule for `.setting-card input[type='number']` to keep the content box aligned without changing behavior.
6. Keep the mobile breakpoint behavior unchanged so the controls still stack under `720px`.

## Verification
1. Review `Controls.jsx` + `App.css` after the CSS change to confirm only the settings controls are affected.
2. Run the existing frontend tests to ensure the `Controls` component still renders and remains interactive.
3. Visually confirm that the `Crop` select and `Duration` input have matching height and aligned top/bottom edges on desktop.
