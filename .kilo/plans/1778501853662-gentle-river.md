# UI copy and density cleanup plan

## Goal
Make the `Files`, `Settings`, and `Queue` panels visually tighter and cleaner, and replace the awkward hero description with copy that states what the app enables rather than telling the user to "monitor a compact batch queue".

## Findings
- The hero description is defined in `ui/src/i18n/translations.js` for `en`, `ru`, and `ua`.
- The visual density for the three panels is mostly controlled from `ui/src/App.css`.
- The largest contributors to the bulky look are:
  - `.panel { padding: 20px; }`
  - `.stack { gap: 16px; }`
  - `.upload-box { gap: 12px; }`
  - `.setting-card { min-height: 156px; padding: 14px; gap: 12px; }`
  - `.file-item`, `.queue-item`, `.result-item { padding: 12px 14px; }`
  - `.queue-item` internal gaps and header margins
- The existing component structure in `FileUpload.jsx`, `Controls.jsx`, and `QueueList.jsx` is already simple enough that this can likely be solved with CSS-only changes.
- Current tests do not appear to assert the hero description text directly, so copy changes are unlikely to require test updates.

## Implementation plan
1. Update the hero description in `ui/src/i18n/translations.js`.
   - Replace the English text with a capability-focused sentence.
   - Keep the meaning aligned in Russian and Ukrainian so the landing copy stays consistent across locales.
   - Prefer wording around: upload local videos, choose an exact range, split into clips, apply crop presets, process locally.

2. Tighten the three main panels in `ui/src/App.css`.
   - Reduce padding on `.panel` and related spacing between headings and body content.
   - Reduce vertical gaps in `.stack`, `.controls-panel`, `.controls-header`, `.upload-box`, `.file-list`, and `.queue-list`.
   - Reduce card/item padding for `.setting-card`, `.file-item`, and `.queue-item`.

3. Improve readability while making the layout denser.
   - Rebalance text spacing for `.hint`, `.field-help`, `.queue-range`, and `.queue-meta`.
   - Slightly reduce overly tall min-heights such as `.setting-card` and related copy wrappers.
   - Keep title/body hierarchy clear so the UI looks cleaner rather than merely compressed.

4. Preserve mobile behavior.
   - Recheck the existing `@media (max-width: 720px)` and `@media (max-width: 980px)` rules.
   - Ensure reduced padding does not make touch targets too small or collapse the content visually on narrow screens.

5. Only add markup hooks if CSS alone is insufficient.
   - If styling needs more precise control, add minimal class wrappers in:
     - `ui/src/components/FileUpload.jsx`
     - `ui/src/components/Controls.jsx`
     - `ui/src/components/QueueList.jsx`
   - Keep structure changes minimal and avoid behavior changes.

## Validation after implementation
- Review the affected panels in the browser layout for consistent spacing and cleaner hierarchy.
- Run targeted UI tests only if implementation touches component markup or causes any failures in existing test coverage.
- Do not perform manual runtime verification beyond normal inspection unless explicitly requested.
