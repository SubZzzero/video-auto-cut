# UI Redesign Plan: Two-State Layout Aligned To Mockup

## Goal
Rebuild the frontend so it actually matches the visual intent of `img/example.png` while keeping the current local video-processing workflow, queue behavior, crop/range editing, translations, and API contract intact.

## Why The First Attempt Failed
- It treated the mockup as a full-time layout instead of an empty-state landing composition.
- The empty state became too heavy: cards were too large, typography too loud, and the native file input visually broke the design.
- The active state became structurally wrong: the large `Settings` editor sat between two tiny side cards, which made the whole screen feel accidental instead of designed.
- The top branding block still occupied too much attention compared with the centered card cluster.
- The implementation optimized for “styled functionality” instead of visual fidelity to the sketch.

## Correct Design Model
The UI should have two clearly different visual states.

### State 1: Empty Landing
This state should be close to the mockup.
- Three compact cards centered in one horizontal composition: `Files`, `Settings`, `Queue`.
- `Files` is the only actionable card.
- `Settings` and `Queue` are calm placeholders with short helper copy.
- Cards should be visually light, narrow, and evenly spaced.
- Top-left title and top-right language switcher should remain extremely subdued.
- The background should stay visually dominant and spacious.

### State 2: Active Workspace
This state begins as soon as at least one file is selected.
- The layout should stop pretending to be the landing mockup.
- The page should turn into a balanced workspace with the same visual language.
- `Settings` can become the dominant center column because it contains the editor.
- `Files` and `Queue` become usable side panels with consistent vertical alignment.
- The screen should feel intentional as a tool, not as a stretched landing page.

## Layout Strategy
1. Add explicit empty/active layout modes in `ui/src/App.jsx`.
   - Compute `hasFiles = queueItems.length > 0`.
   - Apply mode-specific shell classes such as `app-shell-empty` and `app-shell-active`.
   - Keep the same functional component order, but let CSS change the composition by state.

2. Redesign `ui/src/App.css` around stateful layout instead of one shared grid.
   - Empty mode:
     - center the three cards vertically and horizontally
     - fixed compact widths
     - short card heights
     - stronger fidelity to `img/example.png`
   - Active mode:
     - move from centered hero composition to a practical top-aligned workspace
     - use a real three-column tool layout with a larger middle column
     - keep side panels visually related to the center panel
   - Avoid one grid trying to satisfy both states.

3. Keep the global background treatment, but reduce visual noise where it competes with content.
   - Preserve the supplied background image.
   - Keep the subtle grid and glow treatment restrained.
   - Ensure the cards remain the focal layer in both modes.

## Component Changes
4. Rework `ui/src/components/FileUpload.jsx` to feel designed instead of browser-default.
   - Replace the always-visible raw file input with a styled trigger that fits the mockup.
   - Keep the native file input accessible, but visually hide it behind a custom button or label.
   - Empty mode:
     - show only the compact call to action and empty copy
   - Active mode:
     - show the selected file list in a denser, cleaner side-panel format
   - Preserve current upload behavior and accessibility labels.

5. Rework `ui/src/components/Controls.jsx` so the empty state stays compact.
   - Empty mode:
     - render only a compact placeholder card matching the mockup mood
     - do not reserve space for the full editing experience
   - Active mode:
     - render the real editor layout
     - reduce visual weight in headings, spacing, and helper copy so the card feels tighter and more premium

6. Rework `ui/src/components/QueueList.jsx` to behave like a placeholder first and a tool panel second.
   - Empty mode:
     - keep it compact and informational
   - Active mode:
     - expand naturally into a usable queue panel
     - keep internal scrolling, but make the panel height and rhythm consistent with the active layout
   - Tone down status badges if they feel too dashboard-like for the intended aesthetic.

7. Tune `ui/src/components/VideoRangeEditor.jsx` only if needed for density and layout fit.
   - Prefer CSS-only compaction first.
   - If needed, add minimal structural wrappers for spacing groups.
   - Do not change crop/range behavior.

## Visual Direction Adjustments
8. Tighten the visual language.
   - Reduce card padding, icon-box size, and title scale in empty mode.
   - Make placeholder cards closer to the sketch: simpler, calmer, more spacious.
   - Remove any “generic glass dashboard” feeling.
   - Keep the look dark, local-tool oriented, and deliberate.

9. Treat the toolbar as secondary UI, not part of the hero.
   - Keep the title as a very small caption.
   - Keep the language control small and quiet.
   - Prevent the top row from pulling focus away from the card composition.

## Expected File Changes
- `ui/src/App.jsx`
- `ui/src/App.css`
- `ui/src/index.css`
- `ui/src/components/FileUpload.jsx`
- `ui/src/components/Controls.jsx`
- `ui/src/components/QueueList.jsx`
- Possibly `ui/src/components/VideoRangeEditor.jsx` if a minimal wrapper is needed for active-state density.

## Guardrails
- Do not change queue processing logic.
- Do not change API calls.
- Do not change translations unless a current string is clearly too long for the design.
- Do not force the active editing workflow into the compact empty-state composition.
- Prefer the smallest structural changes that unlock a clearly better layout.

## Validation
- Run frontend tests in `ui/`.
- Run `npm run lint` in `ui/`.
- Do not run manual runtime verification unless explicitly requested.

## Implementation Focus
The next implementation must optimize for this priority order:
1. Empty state visual fidelity to `img/example.png`
2. Clean active workspace composition after file selection
3. Preservation of existing frontend behavior
