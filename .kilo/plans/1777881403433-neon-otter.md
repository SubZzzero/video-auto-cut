# Plan: refresh the UI to a dark minimal yellow-accent theme

## Goal
Refresh the current React UI so it matches a strict dark minimal direction: solid black page background `#0b0f14`, solid card background `#121821`, flat surfaces, one accent color only, and a primary button that uses `#facc15` with hover `#eab308` exactly. Avoid blue, purple, green, gradients, and glassmorphism.

## Current findings
- Frontend styling is centralized in `ui/src/index.css` and `ui/src/App.css`, so the redesign can stay mostly CSS-first.
- The current theme conflicts with the requested direction in multiple places: gradient page background, translucent panels, backdrop blur, blue/green button gradients, cyan links, and colored status/progress treatments.
- UI structure is already split into small components (`FileUpload`, `Controls`, `QueueList`, `ResultList`, `LanguageSwitcher`, `ProgressBar`), which supports a minimal visual refresh without changing processing logic.
- Most components rely on shared class names rather than inline styles, so a large portion of the change should be achievable without touching business logic.
- `StatusPanel` has its own colored state styles and tests, but it is not currently rendered in `App.jsx`; if any shared state styles remain, they still need to be normalized to the single-accent palette.
- Existing frontend tests are behavior/text focused, so a visual refresh should only require test updates if markup changes become necessary for better styling hooks.

## Implementation plan
1. Rebuild the global theme foundation in `ui/src/index.css`.
- Set `:root` and `body` to the requested solid dark background palette.
- Remove the current radial and linear gradients completely.
- Define neutral text, border, and surface colors around the new black/card backgrounds.
- Update global `a`, `button`, `input`, and `select` defaults so focus and emphasis use the yellow accent instead of cyan or other hues.

2. Flatten the main layout and panel styling in `ui/src/App.css`.
- Replace translucent panel backgrounds with solid `#121821` cards.
- Remove `backdrop-filter`, colorful borders, and other glassy effects.
- Keep the current responsive layout structure, but tighten panel feel toward a flatter, sharper visual language.
- Preserve readability on desktop and mobile without introducing decorative effects.

3. Restyle interactive controls around one accent color.
- Change the primary action button to use `#facc15` exactly, with `#eab308` on hover.
- Restyle inputs, selects, and language controls with neutral dark fills and yellow focus states.
- Keep disabled controls readable through opacity and neutral contrast, not alternate accent colors.
- Ensure the file picker area fits the same flat dark system.

4. Normalize queue, result, and progress visuals.
- Convert progress fills to yellow-only.
- Remove green/blue/cyan status coloring from badges, metrics, and borders.
- Use neutral surfaces plus typography, spacing, and label copy to distinguish queued, processing, success, and error states rather than separate color families.
- Keep output links aligned with the single-accent rule.

5. Make minimal JSX changes only where CSS alone is insufficient.
- If the native file input or action areas need better styling hooks, add small wrapper elements or classes in the affected components.
- Keep component boundaries intact and avoid any processing or API-flow changes.
- If shared state UI such as `StatusPanel` still references off-theme classes, bring it into palette compliance even if it remains unused.

## Validation plan
1. Verify the CSS palette after the refactor.
- Check `ui/src/index.css` and `ui/src/App.css` for removal of gradient backgrounds and off-theme blue/purple/green values.
- Confirm the primary button uses `#facc15` and hover uses `#eab308` exactly.

2. Run targeted frontend automated checks.
- Execute the existing frontend test subset to confirm the redesign did not break component behavior.
- Update tests only if a necessary markup change affects selectors or semantics.

3. Skip manual runtime verification unless explicitly requested.
- Per project rules, do not run manual frontend startup or browser checks unless the user asks for it during implementation.

## Expected impact
- The app will read as darker, cleaner, and more consistent with a flat minimal UI.
- Yellow becomes the only accent for primary action, focus, links, and progress.
- The redesign should stay frontend-only and avoid changing queue logic, API behavior, or translations.

## Risks to watch
- Native file input styling may force a small markup adjustment to achieve a cleaner flat appearance.
- Using a single yellow accent everywhere can hurt hierarchy if overused, so the accent should stay limited to action/focus/emphasis.
- Unused but existing styles such as `StatusPanel` can drift from the theme if they are not normalized together with the shared CSS.
