# Project Context And Cleanup Plan

## Actual Current State

- The repository already implements the target local MVP and is beyond the old step-by-step bootstrap phase.
- Backend exists and is wired: FastAPI app, `/process`, `/jobs/{job_id}`, `/health`, static `/outputs`, background processing, in-memory job store, FFmpeg chunk trimming, OpenCV-based metadata/frame-size reads, centered and manual crop presets.
- Frontend exists and is wired: React + Vite app, multi-file queue, local preview, editable start/end range, draggable crop frame, polling progress, result links, and EN/RU/UA translations.
- Local tooling exists: `scripts/run_local.py`, Python/ESLint/Vitest/Pytest config, README instructions.
- The root `plan.md` is outdated: it is still written as a future roadmap, mentions face detection / smart crop behavior that is not present in the current code, and no longer reflects the implemented product boundary.

## Confirmed Cleanup Candidates

### Repository/runtime artifacts
- Local caches and generated directories exist in the workspace but are already ignored: `__pycache__/`, `.pytest_cache/`, `.ruff_cache/`, `.venv/`, `ui/dist/`, `ui/node_modules/`, `outputs/`, `temp/`, `.coverage`.
- Empty local directories exist and should be reviewed for necessity: `logs/`, `packaging/windows/`.

### Frontend code that appears unused
- `ui/src/components/StatusPanel.jsx` is tracked and tested but is not rendered from `ui/src/App.jsx`.
- `ui/src/components/StatusPanel.test.jsx` only covers that orphaned component.
- `ui/src/utils/queue.js:deriveScreenState()` is exported but unused.
- `ui/src/i18n/translations.js` contains `statusTitle`, `statusEmpty`, `statusMetrics`, `screenStates`, `translateScreenState()`, and `formatStatusSummary()` branches that appear to exist only for `StatusPanel`.
- `ui/src/App.css` contains `.status-*` styling tied to the orphaned status panel.

### Backend code that appears unused
- `app/config.py` exports `DEFAULT_POLL_INTERVAL_MS` and `MAX_BATCH_SIZE`, but no code references them.
- `app/video/ffmpeg.py` contains `build_segment_command()`, but the splitter uses only per-range trim commands.

### Product/plan/docs mismatch
- `plan.md` must be rewritten from a build roadmap into a maintenance/state document that matches the implemented product.
- README should be checked after cleanup so feature wording matches the final kept code and no removed feature is still documented.

## Execution Plan

1. Baseline the tracked project surface.
   - Re-check tracked files and the current diff before edits.
   - Separate ignored local artifacts from tracked cleanup targets so implementation only changes intentional project files.

2. Rewrite `plan.md` to reflect the real product state.
   - Replace the old future-MVP roadmap with an English document that describes the current architecture, delivered scope, known constraints, and remaining maintenance work.
   - Remove outdated claims such as face detection / smart subject centering if they are not implemented.
   - Preserve the backend-first architecture and local-only constraints from `AGENTS.md`.

3. Remove confirmed unused frontend code.
   - Delete `StatusPanel.jsx` and its test if no live entrypoint references them.
   - Remove `deriveScreenState()` if nothing consumes it.
   - Prune status-panel-only translation helpers/keys and matching CSS blocks.
   - Update any frontend tests affected by those removals.

4. Remove confirmed unused backend code.
   - Delete unused config constants from `app/config.py`.
   - Delete `build_segment_command()` from `app/video/ffmpeg.py` if no tests or runtime paths depend on it.
   - Re-run search after edits to ensure no dead imports remain.

5. Review empty or placeholder directories.
   - Remove `logs/` and `packaging/windows/` only if they are truly unused and undocumented.
   - Leave `.kilo/plans/` history untouched unless explicitly requested, because it is workflow metadata rather than app runtime code.

6. Reconcile docs with the cleaned codebase.
   - Adjust README only where cleanup changes documented behavior or structure.
   - Keep feature descriptions aligned with the actual shipped flow: local queue, manual range trim, crop presets, polling, outputs.

7. Validate after cleanup.
   - Run project searches to confirm deleted symbols have no remaining references.
   - Run the relevant automated checks only; do not do manual runtime verification unless explicitly requested.
   - Minimum expected validation after implementation: backend tests touching edited modules, frontend tests/lint for edited UI files, and `ruff check .` if Python files change.

## Expected Outcome

- The repository surface matches the real delivered MVP.
- `plan.md` becomes a truthful source of project state instead of an obsolete roadmap.
- Orphaned UI/backend code is removed without changing the working upload/queue/process/poll flow.
- Documentation and tests stay aligned with the cleaned implementation.
